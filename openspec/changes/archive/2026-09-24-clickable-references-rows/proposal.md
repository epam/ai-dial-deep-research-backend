## Why

A reader who finds a source in the References section cannot open it from there. They have to find
an inline citation of that source in the report body and click its pill, and a source whose only
citation sits in a long paragraph is hard to find. The inline citation mechanism already knows how to
open both kinds of source, so a row can reuse it.

Pill titles are also cut to 20 characters by default, so a pill reads `Market Outlook 2025…, page 2`
and a reader cannot tell from it which publication it names. A client with room for whole titles
gains nothing from the cut, so whole titles are the better default.

## What Changes

- **`max_pill_title_chars` defaults to null**, so every pill shows its leading part whole unless a
  channel sets a budget. The property, its floor of 10 and its meaning are unchanged, and a channel
  that sets a number keeps getting shortened pills.
- **A References row whose source can be opened carries a pill in its first cell.** The first cell's
  text is replaced by a `<cit>` marker tag, and an annotation of its own claims that tag, so the
  source's name is rendered as a pill. The pill opens the same thing an inline pill of that source
  opens: a document's shared PDF, or a dataset's portal page through the card's open-in-browser
  action.
- **A row is openable on the condition its inline citations are.** A document row needs a PDF URL
  from the file-sharing tool, and a dataset row needs a URL a browser can open from the
  dataset-metadata tool. A row whose source fails its condition keeps its first cell as plain text,
  exactly as today.
- **A document row opens its document at page 1.** A References row names the whole document rather
  than a location in it, so it opens where the document begins. The pill still sends a `pdf_bbox`
  selector on page 1, because the document viewer needs a page to open at.
- **A row pill's label is the first cell's value alone.** It carries no `, page <ix>` and no
  ` dataset`, on the pill and on the card, because the row already sits in a table titled by the kind
  of source and a References row names the source, never the cited location. The label falls back
  to `doc <id>` or the URN exactly as the cell does. The channel's pill budget applies to it as it
  does to every other pill.
- **Row annotations join the same `custom_content.annotations` array**, numbered after the inline
  ones. A failed References build drops the row annotations together with the section.
- **Inline pills are unchanged**: they keep their `, page <ix>` and ` dataset` trailing parts.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `report-citations`: the requirement "The References section is built by the app from the cited
  sources' metadata" replaces its rule "No row is interactive in this iteration" with openable rows,
  and its scenario "The built section carries no link" with scenarios for an openable and a
  non-openable row. The requirement "A converted citation is a marker tag in the text and an
  annotation that names it" says the array also carries row annotations, and no longer speaks of a
  default budget of twenty. The requirement "A citation failure costs the citations, never the
  report" says a failed References build also costs the row annotations.
- `application-config-schema`: the requirement "The citation pill's title budget is per channel"
  gets a null default and covers row pills.
- `research-execution`: the requirement "Report node writes the final cited report and is the only
  assistant content" says the References section names in text only the sources whose citations did
  not convert, and names the others by a pill.
- `logging-policy`: the requirement "INFO request skeleton" says the (8c) annotations count leaves
  out the annotations of References rows.

## Impact

- `src/dial_deep_research/app_properties.py`: the default of `max_pill_title_chars` becomes `None`,
  and its field description says so and names row pills.
- `docs/generated-app-schema.json`: regenerated by `make format` from the model.
- `src/dial_deep_research/app/research/citations.py`: a builder for a row's annotation, reusing the
  document and dataset annotation bodies without their trailing parts.
- `src/dial_deep_research/app/research/references.py`: a row can carry a marker tag that replaces its
  first cell's text; the module docstring's "No row is interactive" paragraph is rewritten.
- `src/dial_deep_research/app/research/runner.py`: the References build receives the document URLs,
  the dataset sources and the number of inline annotations, and its row
  annotations are sent in the same array as the inline ones.
- `tests/test_references_section.py`, `tests/test_report_delivery.py`, `tests/test_app_properties.py`:
  new and updated cases for row pills and for the null default.
- `docs/architecture.md`: the citation-step paragraph describes openable rows and the null default.
- No change to `dial_conf/core/applications-template.json`, because no required property changes,
  and none to the annotations demo, which builds no References section and already passes no budget.
